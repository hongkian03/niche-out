Invitation generation consumes the validated configured origin and six-digit code. It produces the exact /join URL and code-prefilled QR payload, retaining leading zeroes. Strict shape validation rejects credentials, fragments, alternate paths and inconsistent QR targets. The runtime comparison helper checks the invitation against the configured origin. The fixture's game.example.com hostname is illustrative.

Every host complete view has a strict hosting status. Starting and connecting carry no diagnostics. Ready and reconnecting carry the sanitized public origin. Failed carries only a fixed reason code. The schemas reject raw connector output, credentials and hosting details added to player views. A host Lobby cannot enable Start while hosting is unready. Ready/reconnecting lobby invitations must match the supplied hosting origin. The server still owns proving readiness, role filtering and exact configuration equality.

TUNNEL_NOT_READY represents a temporary unavailable host operation with HTTP 503 metadata. The game.closed schema adds public-origin-changed while retaining existing terminal reasons. Normal tunnel reconnects are represented by hosting status rather than closing/replacing a game. Rounds, scoring, pack validation, tab control and uncertain-operation semantics retain their existing contracts.
