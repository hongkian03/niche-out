# E1-S10 · Platform lifecycle and release inventory

**PASS for the available Mac feasibility experiments.** On an M3 Pro, macOS 26.5.2, Darwin 25.5.0, Node 24.22.3, ran `npm run probe:platform`. A temporary C helper compiled with Apple's clang and sampled both mach_continuous_time and mach_absolute_time. Across an awake 300 ms interval both advanced about 303.7 ms. The foreground process requested idle-system-sleep prevention with caffeinate -i -w and its own PID. The probe found its precise helper PID and active assertion in pmset, then checked that the process and assertion disappeared after explicit quit, stdin EOF, SIGHUP and forced launcher termination. All four cleanup cases passed. [Platform fixture](../../../probes/platform/run.mjs) · [Proposed adapter interface](../../../probes/platform/boundary.ts)

**NOT RUN** for physical sleep and wake, console window closure on a packaged build, address changes, or real clock-setting changes. Sleep would interrupt the operator's machine. During E5 validate awake timing, sleep-inclusive elapsed time and one-phase recovery together. Use the watch mode in the [checklist](EPIC-1.md) to record a physical sleep sample. The production clock must work across sleep with no ordinary wall-clock dependence. E5 owns foreground lifetime, power release, unsupported-environment notices and cleanup on termination.
