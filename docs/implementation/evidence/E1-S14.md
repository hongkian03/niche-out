## Contributor setup and integrity

Run `npm run setup:tunnel` from the project root using the pinned Node runtime. This invokes `node scripts/install-cloudflared.mjs`. It explicitly downloads the current platform's pinned asset into a temporary directory under ignored `tooling/`, checks the exact byte size and archive digest, checks the archive contains only the expected executable, verifies the executable digest and replaces the local tooling binary. It cleans up temporary downloads. Run `npm run verify:tunnel` (the installer with `--verify`) to check the installed binary without a download. Neither script runs during packaged game startup. [Installer](../../../scripts/install-cloudflared.mjs)

The tunnel runner also verifies the selected executable SHA-256 before executing its version command or spawning it, including CLOUDFLARED_PATH overrides. It requires the exact pinned version and selects cloudflared.exe on Windows. Local checks passed for Mac/Linux/Windows default filenames, the installed Mac binary, rejection of a corrupted custom-path fixture and runner syntax. No new public endpoint was opened for these checks. [Runner integrity helper](../../../probes/tunnel/connector-binary.mjs)

Both commands passed on the available Apple M3 Pro, macOS 26.5.2 arm64, Node 24.22.3. The resulting binary reported `cloudflared version 2026.11.0 (built 2026-11-12-12:18 UTC)`. The probe can use `tooling/cloudflared`, with an explicit CLOUDFLARED_PATH override. `codesign --verify --verbose=2 tooling/cloudflared` returned valid on disk and satisfaction of its designated requirement. That local check does not establish the project's final signing/notarization or clean-machine Gatekeeper behavior.

For Mac assets the release body labels values as tgz checksums, but the downloaded arm64 tgz hashes to `8c2f90277ef06a6080bb40b964d33f09f1188102f8798f2e344174b6cf41accf`, matching the GitHub asset digest. The x64 executable value comes from the release body and awaits actual artifact verification. Windows and Linux raw executable digests agree between release body and asset metadata. All checks authenticate against the pinned official GitHub HTTPS metadata; they are not a new project signature.

## Credential and process boundary

For an event, the operator supplies the named tunnel account/domain configuration and scoped run credentials. Use a private local configuration location outside the source/archive and a token file restricted to that user, with OS-specific permissions. The installed connector supports `tunnel run --token-file`; its exact help was inspected. Do not pass a token value on a logged command line. Account-wide origin certificates, run tokens, cookies and bootstrap secrets stay out of manifests, fixtures, URLs, package archives and evidence. The developer Quick Tunnel probe needs no named-tunnel credential but has temporary-address semantics and provider development limits.

Launch the installed connector as an owned child with `--no-autoupdate`; each release explicitly upgrades it. Its upstream is the configured loopback server, and its metrics endpoint must remain loopback. Public readiness requires successful endpoint verification and real browser transport evidence. A live child PID alone is insufficient. Filter connector output into sanitized statuses; avoid debug logging because the binary's own help warns that it logs request URLs and request/response headers.

E5-S01 owns a bounded startup/restart policy and actionable errors. Preserve the running game during same-origin reconnect, and require a fresh game after public-origin replacement. Stop accepting application work, notify reachable clients, close sockets, request connector shutdown and reap descendants. The connector's documented CLI grace period defaults to 30 seconds; packaged cleanup must select an explicit bounded period and escalate termination if necessary. On Windows test a kill-on-close Job Object; on Mac/Linux test launcher closure and abnormal parent exit with the selected ownership helper. E5-S02–S05 own these real process-tree and power/suspend tests. The S13 evidence records whichever short-lived probe connector lifecycle paths actually ran.
