# E1-S09 · Import worker measurements

**PASS on the available Apple Silicon host.** On November 13, 2026 the [probe](../../../probes/import/run.mjs) ran nine isolated scenarios on an Apple M3 Pro, 18 GiB physical memory, macOS 26.5.2 (Darwin 25.5.0), arm64 Node 24.22.3, Zod 4.6.7. Reproduce from the project root with `npm run build -w @rarity/contracts` followed by `npm run probe:import`. Each line of output contains exact byte values and the validation-stage measurements. Fixtures are generated outside the measured child process and cleaned up.

The parent transfers an owned byte buffer to one worker. The worker decodes strict UTF-8, parses JSON, validates it against the shared schema and sends the normalized pack back through structured clone. Each case uses a fresh Node process. The parent samples every 5 ms and when it receives messages. The worker samples after decode, parse, validation and cloning. RSS covers the entire process and its native allocations. The isolate heaps, externally accounted allocations and ArrayBuffer readings are sampled independently and can overlap. The OS high-water mark captures short peaks interval samples may miss. Measurements include the worker's runtime and validation library.

The worker ran with a 256 MiB old-generation ceiling. Admission checked `process.availableMemory()` against 256 MiB plus eight times the input size and V8 `total_available_size` against 128 MiB plus eight times the size. Both real readings admitted the two packs. An oversized fixture (10 MiB + 1 byte), injected unknown/insufficient available memory and insufficient heap all failed before worker creation. Malformed JSON and a schema-invalid pack produced controlled validation failures. A deliberately stalled worker reached the actual 10-second timeout and terminated at 10,008 ms. Each case checked the prior committed fixture's identity and contents after staging or rejection.
