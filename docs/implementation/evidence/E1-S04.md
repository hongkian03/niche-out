## Implementation handoff

- A full page obtains a server-issued tab ID and request prefix. An ordinary envelope carries protocol version, instance, tab ID and request ID. Socket command name is its event name. A request ID combines a base64url-style prefix, a period and a positive safe-integer sequence. Join may carry a null game ID. Submit requires the round ID and current control generation. Remove takes a target ID. No payload provides the requesting player's authority.
- Use the actual received byte length before decoding ordinary HTTP or socket input. The shared helper enforces 4 KiB. Raw import has a separate 10 MiB ceiling. The server must enforce its streaming bound before allocating a complete body. Pack field errors carry path segments, including numeric array indexes, so the UI can format an exact authoring path. GET query fields are strings. Omit the snapshot's game ID in Setup.
- For retry comparison, the canonical fingerprint includes the operation kind and all validated fields. Object property order has no effect. Raw submitted wording and IDs are significant. Fingerprints can contain private values and belong only in server memory. Bind ledger lookup to the authenticated identity and current page. The fingerprint cannot establish authorization.
- Use the same request ID and content for at most two automatic retries after a two-second acknowledgement timeout. On an uncertain host action, resolve the original validated commit, Start or removal. APPLIED returns the original outcome with a current host view at an equal or later revision. NOT_APPLIED requires the server to fence the ID before responding. SUPERSEDED carries the permitted current host context. Authorized duplicate recovery precedes new-operation phase/deadline checks. The ledger and serialized resolution belong to E3-S07/S09–S11.

## Verification

On the Epic 1 working tree, macOS 26.5.2 arm64, Node v24.22.3, Zod 4.6.7 and Vitest 5.1.0, run from the game workspace:

- `npm run typecheck` passed.
- `npm test -- tests/protocol` passed 41 tests in two files, shared with E1-S05. Request tests cover valid/invalid examples for every route and command, wrong versions, required context, forbidden extra fields, same-ID/different-content comparison, upload limits, recovery outcomes, and pre-reveal reply shape.
- `npm run build --workspace ./packages/contracts` generated JavaScript and declarations successfully.

E3 owns authentication, raw-body admission, nonce consumption, actual cache/fence behavior, response loss races and transport integration. Schema acceptance alone cannot prove any of those behaviors.
