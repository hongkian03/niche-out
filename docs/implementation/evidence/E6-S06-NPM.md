## Delivered

- [Release metadata](../../../packaging/release/candidate.json) uses npm schema 2: package/repository/version, host Node range, separate publisher toolchain proposal, MIT metadata, native authentication prerequisites and per-target evidence references. No old standalone `.app`/Windows JS-verifier/bundled-Node blocker remains in the active plan. Deferred values stay explicit, not inferred from copyright.
- [Auditor](../../../scripts/release-audit.mjs) reads actual compressed tarball bytes adjacent to candidate metadata, independent of staging. It checks SHA-256 and npm SHA-512 integrity, complete resource/file/mode inventory, required server/worker/browser/help/example resources, four native hashes and Node-API/source binding, connector catalogue, runtime shrinkwrap versus reviewed lock, source snapshot and packaged notice texts. Unexpected private/developer/credential filenames and unapproved example packs fail validation. This is bounded integrity inspection, not a guarantee that arbitrary secret values could never appear in legitimate application text.
- [Tar reader](../../../scripts/release-tar.mjs) reads in memory without extraction or execution, bounds compressed/expanded input and file count, checks header checksums and terminators, and rejects traversal, duplicate files, links and unsupported extensions. Current npm candidate packing passes this supported format.
- [Review planner](../../../scripts/release-plan.mjs) runs the audit, binds the exact artifact/inventory hashes, and lists deferred owner/notice/native/target/publisher gates. It has no execution mode and always keeps public readiness/authorization false. Registry attestations belong after explicitly authorized candidate upload in S12, not before local review. Filled configuration fields cannot establish native authentication or passing target reports.
- [Notice assembler](../../../scripts/release-notices.mjs) copies original installed upstream permission files verbatim. The conservative source production graph covers external server and bundled browser dependencies, plus the esbuild generated-helper notice; conditional unused browser code may be included. Coverage is not exact bundle attribution or legal clearance. The manifest separates complete texts, absent upstream permission text and missing license metadata.
- [Npm assembler](../../../scripts/npm/assemble.mjs) includes `release/notices.json`, copied permission files, `release/build-manifest.json` and `release/source-files.json` in the tarball and its resource hashes. Hosts still require no compiler, install hooks or bundled Node. No game runtime/transport/scoring behavior changed.
- [Build manifest](../../../scripts/build-manifest.mjs) now saves its sorted source path/hash list for independently checking the aggregate source digest. It includes no source contents or test-answer fixtures. Generated reports in `epic6-npm-release/` are excluded to avoid recursive artifact hashes. Historical archive checksum verification still works through the relocated helper in `scripts/package-lib.mjs`.
- Release/operator/developer guides, owner decisions and the story tracker are reconciled. Existing network limitations and deferred platform qualifications remain.

## Findings and fixes

The previous auditor checked legacy archive sidecars and separately staged notices; those checks could not prove npm tarball contents. It now reads the compressed package itself. Previous candidate metadata incorrectly treated the existing MIT choice as unresolved and required obsolete standalone containers; schema 2 fixes those assumptions. Earlier npm assembly omitted a full source snapshot and did not copy browser-bundled dependency license texts; both are now included. The historical archive verifier imported a checksum helper from the old auditor; moving that helper to the shared package library preserves that verifier while retiring archive assumptions from the active release path.

Remaining notice findings are deliberately retained: `abstract-logging@2.0.1` ships only a link rather than complete permission text; `xmlhttprequest-ssl` has complete MIT text but omits its license metadata label; the separately downloaded cloudflared linked-dependency notice review is incomplete. No copyright text was invented. Cloudflared executables are not redistributed inside the npm tarball. The earlier Go inventory remains a read-only reference, not license clearance.
