# E1-S08 · Browser tab continuation

**PASS in Chrome 157.0.8103.51** on macOS 26.5.2 arm64, Node 24.22.3. Ran `npm run probe:tabs` using a disposable browser profile, real sessionStorage, a private-IP HTTP origin and one synthetic admitted membership. The application-level experiment validates discovery, command inputs and grants against the compiled contracts. Each document bootstrap receives a fresh server page ID. The cookie stays HttpOnly; the server stores only one current grant. The instrumented client can discard a response while the server retains the operation.

| Step | Observed controller outcome |
| --- | --- |
| Initial page, then loaded-page resume | Generation 1 both times |
| Reload controlling page with unsent text | New page ID, generation 2; draft cleared |
| Two opener-created tabs copy the same token, both discover, then submit concurrently | One wins generation 3; other receives CONTROL_CONFIRMATION_REQUIRED |
| Prior controller reconnects; another tab copies its stale record | Loaded document gets TAB_SUPERSEDED; new document requires explicit takeover |
| Explicit claim, discard its acknowledgement, retry same request | Generation 4 recovered; old controller superseded |
| Open independent tab without opener, discard successful resume reply, retry same request | Generation 5 recovered, one controller at end |

A separate smoke run opened the manual page, checked its current-control button and confirmed the displayed generation advanced on reload. Storage contained only the four agreed continuation fields. No draft or proof was printed in the report. The test opens the two distinct popup pages before racing requests; the harness verifies that their server IDs differ. The loaded-page scenario reuses document state for a new HTTP exchange. Production Socket.IO disconnection and acknowledgement loss remain E3-S04/S13 checks.

**NOT RUN** for a desktop browser's native Duplicate Tab menu, Safari/Firefox/mobile session restoration and process eviction. Opener copies exercise a real browser copy of sessionStorage and server-side consumption; native duplication may use a different document lifecycle. Use the manual probe and target devices before signing off those recovery paths. [Scenario runner](../../../probes/tabs/run.mjs) · [Handoff and test steps](EPIC-1.md)
