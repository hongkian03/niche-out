X-Forwarded-For was present in the observed public requests. It is recorded only as a boolean and confers no authority. The shared ingress helper checks the actual loopback peer, exact configured upstream Host and permitted Origin rules. Its absent-Origin exception is limited to GET/HEAD without a WebSocket upgrade. Authentication remains separate. The local real-HTTP self-test additionally rejects wrong Host, missing mutation Origin, forged forwarding metadata and unauthorized uploads, while checking same-ID outcome recovery and body bounds.

## Failures found and changes made

Fresh Quick Tunnel hostnames initially failed through the Mac's normal DNS resolver with ENOTFOUND. One diagnostic comparison showed public resolvers resolving the new name and a targeted TLS request reaching the application with HTTP 200; the normal resolver subsequently caught up. No OS DNS settings were changed. The runner now allows up to three minutes for public readiness, reports bounded progress/error categories, and publishes its ready invitation only after the expected public health response. A URL printed as allocated is not readiness evidence.

The first browser launch was denied by the execution sandbox. The authorized test was rerun with the needed local browser-launch permission and passed. This was a test-environment restriction, not an application or provider result.

Final review corrected the Windows default connector filename to `cloudflared.exe` and added manifest SHA-256 verification **before executing** either the default or explicitly selected connector. The version must also equal the pinned version. Available-Mac integrity, a corrupted override fixture and platform filename choices were checked locally. Final review also added sanitized phone connection codes and numeric HTTP statuses, without changing network behavior or exposing raw error strings.
