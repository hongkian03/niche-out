# E1-S11 deployment contract evidence

Current application implementation and testing instructions: [managed hosting handoff](EPIC-1-MANAGED.md). Earlier evidence and scope-decision notes below are retained as dated history.

> **Applicability update, November 14, 2026:** This is evidence for the initial executable contract. The approved [managed-session decision](../../TUNNEL-MIGRATION.md) plans E1-S15–S20, including removal of the event-requires-named restriction. These results do not claim that expansion is implemented; consult the [master tracker](../../IMPLEMENTATION-PLAN.md).

Implemented November 14, 2026 using Node 24.22.3, TypeScript 5.9.3 and Zod 4.6.7 on macOS arm64. [Contract implementation](../../../packages/contracts/src/deployment.ts) · [Boundary tests](../../../tests/contracts/deployment.test.ts)

The configuration is strict and secret-free. It accepts one canonical public HTTPS DNS origin, a 127.0.0.1 listener and explicit upstream Host behavior. A named Cloudflare tunnel is the candidate event configuration. Quick Tunnels are admitted only for the explicitly classified probe purpose. No account, domain ownership, provider capacity or venue connectivity is inferred from schema validation.

```json
{
  "mode": "tunnel",
  "purpose": "event",
  "provider": "cloudflare",
  "tunnelKind": "named",
  "publicOrigin": "https://game.example.com",
  "listen": { "host": "127.0.0.1", "port": 3210 },
  "upstreamHost": "public"
}
```

The example hostname is illustrative and must be replaced with the operator's verified endpoint. Configuration uses canonical origin spelling without a trailing slash or explicit default port. Non-default HTTPS ports are representable. Invalid nested configuration returns Zod field paths. The first provider-specific deployment schema deliberately rejects unreviewed providers until the integration is specified and tested.

The transport helper checks the actual 127.0.0.1 peer, exact configured upstream Host and public Origin. With upstreamHost public, Host must equal the public URL authority. With loopback, Host must equal the literal listener address and port. Supplied Origin must always match. Missing Origin is accepted only for GET/HEAD without a WebSocket upgrade. Forwarded headers are unused by this initial policy. Role authorization, session validation, raw-body bounds and method/route enforcement remain required in E3. Passing a loopback or origin check conveys no host permission.

Cookie options are Secure, HttpOnly, SameSite=Strict, Path=/ and omit Domain. Their secure policy comes from deployment configuration even though the last hop is local HTTP. E3 owns emitting and enforcing the cookie and protecting authenticated state. E1-S13 supplies real edge/header and browser evidence.

Origin continuity compares validated browser origins. Same-origin connector recovery preserves game identity under the agreed lifecycle policy. A changed scheme is invalid for this deployment, and a changed hostname or non-default port requires a fresh game. This helper describes the decision; E5 owns applying it to a running game and connector.

## Verification and pending evidence

`npm run typecheck`, `npm test` and `npm run build -w @rarity/contracts` passed. The combined workspace suite has 118 tests in six files, including 27 added deployment tests. Cases cover malformed origins, private/loopback hosts, wildcard listener, unsafe credentials/paths, wrong or missing Origin, wrong Host and peer, forged forwarding fields, cookie flags and mode restrictions.

Operator account/domain availability, accepted recurring cost, provider plan and venue egress remain inputs for E1-S13. Application/global admission throttles and actual proxy integration belong to E3. A configured hostname is not evidence that it is controlled by the operator or reachable from the intended venue.
