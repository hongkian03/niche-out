# E6-S10 and E6-S11 exact-package verification and readiness

November 19, 2026. The owner authorized parallel execution of S10/S11 under the lean initial npm release policy. Three agents reviewed package checks, recovery/privacy coverage and release claims; the coordinator froze and tested the actual npm candidate. Results, exact hashes, commands and readiness decisions are in the [execution record](epic6-npm-release/s10-s11/summary.json). This report does not authorize S12 publication.

## Scope and selection

The executed host is the available Apple Silicon Mac with its actual hardware, macOS/Darwin, Node/npm and browser versions recorded in the execution record. Supported version ranges/OS floors describe intended compatibility, not evidence that every combination was tested. Intel Mac/Windows/Linux native payloads remain included but unverified/experimental. A fresh installed package on this existing machine is not a clean-machine Gatekeeper/quarantine test.

S10 selects meaningful tests of actual npm bytes: isolated local/global/npm-exec installation with scripts disabled, actual packaged worker and examples, read-only package operation, native helper/clock/ownership, fresh pinned connector preparation and verified warm reuse, corrupt/offline component failure, controlled package damage, production browser game and private owner recovery, foreground process cleanup. Previous tests are carried only through explicit matching runtime-byte inventories. There is no automatic extra stress/device campaign for unchanged code.

## Execution and evidence

- Fresh regression/fixture tests cover source application, release/packaging assertions, private host/session boundaries, resource and connector integrity, corrupt worker/cache files, stale locks, cancellation and version reuse. Exact test counts and outcomes are recorded, not inferred from historic reports.
- The production browser harness drives an actual installed package and its owned temporary Quick Tunnel. It imports through the real worker, rejects an invalid answer before retry, accepts aliases, checks authored scores/joint winners, refreshes final identity, restores administration after closing the host page and clearing public-origin host cookies, and quits. Phone-sized Chrome is emulation, not another physical-phone result.
- Component qualification uses private disposable cache/package copies. The original selected candidate and its installed resources are never intentionally corrupted. Invalid/offline preparation must fail before unverified execution; altered web/native resources must fail their integrity check before hosting. The local/private controller and public game origin stay distinct.
- Owned npm-wrapper/CLI termination checks are separate serialized jobs. Evidence identifies which termination actually ran. No blanket system-security change, privileged installer or publisher certificate is introduced.
- Exact tarball/source/lock/native/connector/notice hashes and actual commands are retained. Reports exclude cookies, private URLs/capabilities, account tokens and uploaded payload contents. Screenshots are player-only.

## Results and changes

The fresh project regression passed **485 tests in 37 files**; **35 standalone packaging/release/npm fixture checks**, typecheck and production assembly also passed. The game-tested candidate passed six installation checks, three native execution checks, seven worker/component/resource checks, six browser/game/recovery checks and three active-wrapper cleanup checks. An altered tarball copy failed both SHA-256 and npm-integrity checks as expected. The final documentation freeze is audited and installed again; its exact outcomes and runtime identity binding are in the execution record.

The real browser run used Chrome 157.0.8103.79 with two 390×844 player viewports. Both players retried rejected answers, used the Fall→Autumn alias and finished two rounds tied on 200. Four answer-phase width checks found no horizontal overflow. Answering/final screenshots were visually inspected for readable input, Submit, standings and recap. Public-cookie removal preserved the separate private controller cookie and recovered the same final scores. Explicit Quit passed. Killing only an independently installed npm wrapper also removed its three owned descendants and closed both listeners.

Two failures were in test assumptions, not gameplay. Default test discovery picked up upstream JavaScript tests inside an ignored Go-download cache; `vitest.config.ts` now selects the project's `tests/` suites. A native idle-sleep assertion test incorrectly expected no other Niche Out host to exist; it now checks its own PID and waits for that process's release. The unrelated running host was left untouched. After these corrections all project tests passed. No game/server/native runtime code changed.

The new `scripts/npm/check-components.mjs` makes actual installed example-worker, cold/warm/offline/corrupt cache and changed-resource checks repeatable. `scripts/npm/smoke.mjs` now waits for visible rejection before retry, measures phone answer width, checks lost-public-cookie recovery and sanitizes retained failure diagnostics. Documentation corrects stale mandatory-signing, universal-platform and promotion claims. The tracker records the scoped handoff; no legacy missing test is converted into a pass.

## Retained limitations

Earlier capacity evidence covers 100 simulated players with 80 WebSocket/20 polling clients and a complete 20-round game on eduroam, with one recovered polling DNS failure. Carry-over requires runtime-byte binding. It does not prove all-polling reliability, 100 physical devices, an 8 GiB host or venue availability. No provider uptime guarantee is claimed. Actual phone/keyboard evidence remains dated; current browser emulation is labelled separately. Physical sleep/terminal/clock/quarantine behavior and wider browser/assistive-tech coverage remain explicit follow-ups.

The host must provide supported Node; Node is not bundled. Game state is in-memory and restart/public-origin replacement requires a fresh session. Optional project publisher authentication is not represented as present. Per-file hashes detect integrity damage and are not an independent publisher identity root.
