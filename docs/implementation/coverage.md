# Requirement and Story Coverage

This is the requirement index for the [implementation backlog](../IMPLEMENTATION-PLAN.md). It contains no execution status. At creation every story was TODO; consult the master tracker for current progress.

Each baseline criterion retains its own row even when several share a story. Implementation stories provide behavior; verification stories supply the required integrated, device, platform, or final-artifact evidence. A mapping is not a passing result. A story can contribute its targeted checks without certifying all later evidence.

The [PRD](../PRD.md#acceptance-criteria), [UI/UX](../UI-UX.md#design-acceptance-criteria), and [architecture](../ARCHITECTURE.md#implementation-contract) remain authoritative. If a criterion changes, update its mappings and downstream gates. New bug/split stories must preserve coverage of the original criterion.

## Gate interpretation

- Historical G1 proves the recorded LAN foundation. S15 revises the session-hosting contract gate for E2; S16–S20 implement and verify the managed hosting feature for E3. S13 findings feed S20; actual event-network/provider qualification remains E6.
- G2 proves the deterministic core and projections.
- G3 proves the actual restricted server/protocol.
- G4 proves the functional built browser game and owned recovery flows.
- G5 requires the four private portable-target/lifecycle results.
- G6 requires the applicable final capacity/device/accessibility/signing evidence through E6-S11.
- E6-S12 adds actual authorized publication; E6-S13 is optional. Site/publication rows do not block the local game or private release-ready handoff.

For example, U05 is implemented in the composer stories but is not fully verified by a 390 px browser screenshot: E6-S04 owns real phone keyboard evidence. Likewise, P03 is not passed by having a 100-player constant; E6-S02 owns declared workload measurements and E6-S04 records the separately tested event-network/provider/device conditions.
